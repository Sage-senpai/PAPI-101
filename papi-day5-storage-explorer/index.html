Typed vs Untyped Queries

Untyped Approach

// 1. Construct storage key (complex)
const key = api.query.balances.account.key(address);

// 2. Fetch raw hex data
const raw = await api.rpc.state.getStorage(key);

// 3. Manually decode (error-prone)
const decoded = api.registry.createType(
  'AccountData',
  raw
);

// 4. Hope the structure is right
const balance = decoded.free;
// Is it .free? .data.free? Who knows!

Problems:

  • ❌ Manual key construction
  • ❌ Raw hex handling
  • ❌ No type safety
  • ❌ Breaks on runtime upgrades
  • ❌ No autocomplete

PAPI Typed Queries

// One line, fully typed
const account = await dotApi
  .query.Balances.Account(address);

// TypeScript knows everything
const freeBalance = account.data.free;
const reserved = account.data.reserved;

// Autocomplete shows all properties
// Type safety guaranteed
// Updates automatically with runtime

Benefits:

  • ✅ One-line queries
  • ✅ Automatic encoding/decoding
  • ✅ Full TypeScript support
  • ✅ Runtime upgrade resilient
  • ✅ Complete autocomplete
